# Parser Studio: полная инструкция по сбору, проверке и выгрузке данных

Это инструкция для пользователя интерфейса Parser Studio. Она описывает полный цикл:

```text
Проект → Источник → Dataset → Шаблон → Workflow → Запуск → Проверка → Excel / API
```

Важное правило: **источник, dataset и workflow для одного запуска должны находиться в одном проекте**. Шаблоны можно использовать в любом проекте, но источник выбирается из проекта текущего workflow.

## Что где хранится

| Сущность | Что это | Где управлять |
| --- | --- | --- |
| Проект | Контур задачи: источники, схемы, datasets и workflows | `Проекты` |
| Источник | URL сайта или загруженный файл | `Источники` |
| Dataset | Текущее состояние собранных записей и история изменений | `Данные` |
| Шаблон workflow | Защищённая или пользовательская заготовка схемы | `Шаблоны workflow` |
| Workflow | Редактируемая схема обработки данных | `Workflows` |
| Run / запуск | Один факт обработки одного источника | `Запуски` |
| Raw artifact | Сырой ответ сайта/файл, использованный в запуске | внутри конкретного запуска |
| Проверка | Очередь новых, изменённых и контрольных записей | `Проверка данных` |

## 1. Создание проекта

Откройте `Проекты` → `Создать проект`.

| Поле | Обязательно | Как заполнить |
| --- | --- | --- |
| `Название` | Да | Человеческое имя, например `Мониторинг ставок банков`. Можно менять позднее. |
| `Slug` | Да | Уникальное техническое имя: только строчные латинские буквы, цифры и дефисы. Пример: `bank-rates-2026`. Нельзя использовать пробелы, кириллицу, `_`, `/`, `!`. Slug не меняется вместе с названием и используется в API. |
| `Часовой пояс` | Да | Обычно `Europe/Minsk`. Влияет на расписание и поле времени наблюдения. |
| `Язык` | Да | Обычно `Русский`. |
| `Описание` | Нет | Кратко: что собирает проект и кто владелец. |
| `Шаблон проекта` | Да | Для новой задачи выбирайте `Пустой проект`, если не нужен демонстрационный набор. |

После создания проекта запомните его: именно его нужно выбирать далее для источника, dataset и новой копии workflow.

## 2. Создание источника

Откройте `Источники` → `Добавить URL`.

### Обязательные поля

| Поле | Обязательно | Правило |
| --- | --- | --- |
| `URL` | Да | Полный адрес, начиная с `https://` или `http://`. Вставляйте именно страницу с данными, а не главную страницу сайта. |
| `Проект` | Да | Тот же проект, в котором будет workflow. |
| `Название` | Да | Понятное имя: `Беларусбанк — депозиты юрлиц`, а не просто `site`. |
| `Режим загрузки` | Да | Выберите предложенный Source Profiler режим; подробности ниже. |

### Как добавить

1. Вставьте URL.
2. Нажмите `Запустить Source Profiler`.
3. Дождитесь статуса ответа и посмотрите предложенный режим.
4. Выберите проект, имя и режим.
5. Нажмите `Создать источник`.

### Выбор режима загрузки

| Режим | Когда выбирать |
| --- | --- |
| `HTTP` | Обычная HTML-страница, данные уже есть в HTML. Это основной вариант. |
| `Playwright` | Страница собирается JavaScript после загрузки; в обычном HTML данных нет. |
| `JSON/XHR` | Source Profiler нашёл JSON API, из которого сайт загружает данные. |
| `Document parser` | Источник — PDF, XLSX, CSV, DOCX или иной документ. |

### Настройки источника после создания

Нажмите на строку источника. Здесь можно изменить URL, имя, режим и флаг `Использовать в общем запуске`.

- Включённый источник участвует в `Запустить все публичные источники`.
- В `Статус доступа` укажите `Публичный доступ`, если сервис может читать страницу без логина.
- `Нужен доступ` означает, что источник исключается из общего запуска до настройки разрешённого доступа.
- Не добавляйте в публичный источник логины, пароли, токены или персональные данные.

## 3. Создание dataset

Dataset — не временный Excel-файл. Это хранилище текущих записей и их версий: workflow добавляет новые ключи и обновляет существующие записи.

Откройте `Данные` → `Создать dataset`.

| Поле | Обязательно | Как заполнить |
| --- | --- | --- |
| `Название` | Да | Человеческое имя, например `Ставки банков`. |
| `Slug` | Да | Уникальный slug по тем же правилам, что slug проекта: `bank-rates`. |
| `Проект` | Да | Тот же проект, что у источника и workflow. |
| `Схема` | Нет, но рекомендуется | Выберите заранее созданную схему, если поля и типы должны строго валидироваться. |
| `Natural key` | **Практически обязательно** | Поля, которые определяют уникальность записи. Без него данные не сохранятся. Перечисляйте через запятую. |
| `Review новых` | Рекомендуется для финансовых данных | Новые записи будут ждать подтверждения перед экспортом. |
| `Review изменений` | Рекомендуется | Изменённые ставки/условия попадут в очередь проверки. |
| `Confidence threshold` | Нет | Порог доверия от `0` до `1`; записи ниже порога будут направлены на проверку. |

### Как выбрать natural key

Natural key не должен меняться при обычном обновлении записи. Он не должен включать ставку, дату сбора или свободный текст условий.

Примеры:

| Тип данных | Хороший natural key |
| --- | --- |
| Депозит | `bank_name, product_name, currency, term, source_url` |
| Токен | `issuer, product_name, currency, source_url` |
| Регуляторная ставка | `indicator_name, currency, source_url` |
| Новости | `url` или `external_id` |

Если ключ выбран слишком широко, разные продукты сольются в одну запись. Если слишком узко, каждое изменение будет выглядеть как новая запись.

## 4. Создание workflow из шаблона

Откройте `Шаблоны workflow`.

### Встроенные шаблоны

| Шаблон | Назначение |
| --- | --- |
| `Universal parser baseline` | Основной AI-парсер HTML-страниц. Это защищённый эталон: его нельзя изменить или удалить. |
| `Веб-страница: таблицы и карточки` | Ручной парсинг повторяющихся HTML-карточек или строк таблицы CSS-селекторами. |
| `JSON API / XHR` | Источник отдаёт JSON. Используйте JSONPath и сопоставление полей. |
| `Документ: PDF, XLSX, CSV, DOCX` | Извлечение данных из файла. |

Нажмите у нужной карточки `Создать workflow`.

| Поле | Обязательно | Правило |
| --- | --- | --- |
| `Проект` | Да | Выберите проект источника и dataset. Шаблон можно взять из другого проекта — это нормально. |
| `Название workflow` | Да | Например `Депозиты юрлиц — рабочая версия`. |

После этого редактируется только созданная копия. Встроенный шаблон и другие workflow не меняются.

## 5. Обязательная настройка workflow

Откройте созданный workflow.

### 5.1. Настройте dataset

1. Нажмите на пустое место canvas, чтобы открыть настройки workflow справа.
2. В поле `Dataset` выберите созданный dataset.
3. Нажмите на узел `Output` и ещё раз убедитесь, что там выбран тот же dataset, если поле доступно.
4. В `Output` задайте `Natural key fields`, если они не наследуются из dataset. Используйте те же поля и тот же порядок, что в dataset.

Данные не будут сохранены, если нет dataset, natural key или результата узла `Mapping`.

### 5.2. Настройте извлечение данных

Для `Universal parser baseline` проверьте узлы:

- `HTTP Request`: URL должен оставаться `{{source.url}}`; не заменяйте его постоянным адресом, если workflow должен работать для разных источников.
- `LLM Extract`: здесь лежит инструкция модели и ожидаемые поля. Меняйте её, если меняется предметная область.
- `Mapping`: обязательный узел. Каждое целевое поле должно соответствовать полю, которое вернул предыдущий узел.
- `Output`: хранение в dataset и natural key.

Для финансового мониторинга обычно нужны следующие поля результата:

| Поле | Когда обязательно | Формат |
| --- | --- | --- |
| `product_name` | Да | Наименование продукта. |
| `source_url` | Да | URL страницы, откуда взяты данные. |
| `bank_name` или `issuer` | Да для банков/токенов | Название организации. |
| `customer_type` | Рекомендуется | Например `legal`, `individual`, `regulator`, `token`. |
| `currency` | Если применимо | `BYN`, `USD`, `EUR`, `RUB` и т. п. |
| `interest_rate` | Если есть ставка | Число без символа `%`. |
| `term` | Если есть срок | Исходный точный текст срока: `12 месяцев`, `180 дней`. |
| `min_amount` | Если опубликована минимальная сумма | Точный текст или число согласно вашей схеме. |
| `conditions` | Нет | Явно опубликованные условия. |
| `observed_at` | Рекомендуется | Время запуска; можно заполнить выражением `now("Europe/Minsk")`. |

Для другого типа данных задайте собственный стабильный набор полей, обновите Mapping, dataset schema и natural key согласованно.

### 5.3. Ручная настройка шаблона HTML

Для шаблона `Веб-страница: таблицы и карточки` обязательно заполните в узле `Extract repeating list`:

| Поле узла | Обязательно | Пример |
| --- | --- | --- |
| `Container selector` | Да | CSS-селектор одной карточки: `.product-card` или `table tbody tr`. |
| `Fields` | Да | Для каждого поля — имя и CSS-селектор внутри карточки. |
| `attribute` | Только для ссылок/атрибутов | Для URL обычно `href`. |

Затем настройте `Mapping`, иначе dataset не получит business records.

### 5.4. JSON API

1. В `HTTP Request` укажите endpoint, метод, параметры, headers и body, если их нашёл Source Profiler.
2. В `JSON Path` укажите путь к массиву записей, например `$.data.items[*]`.
3. В `Mapping` свяжите поля JSON с полями dataset.

Не сохраняйте в workflow API-ключи. Секреты добавляйте в `Подключения` → `Секреты` и используйте предусмотренную подстановку.

### 5.5. Сохранение и публикация

После каждого изменения нажимайте в таком порядке:

1. `Сохранить draft`.
2. `Проверить` — исправьте ошибки графа, если они появились.
3. `Опубликовать` — фиксирует неизменяемую версию, пригодную для расписания.

`Draft` — черновик. `Опубликованная версия` — фиксированная рабочая версия. После изменения графа для расписания всегда публикуйте новую версию.

## 6. Ручной запуск

Перед запуском убедитесь, что источник уже создан **в том же проекте**, что workflow.

1. Вверху редактора в поле `Источник запуска` выберите конкретный источник. Это обязательно для запуска одного сайта.
2. Нажмите `Запустить`.
3. Нажмите `Запустить выбранный источник`.

Если источник не выбран, workflow с `{{source.url}}` не может работать. Интерфейс должен попросить выбрать источник; не пытайтесь запускать с пустым полем.

### Общий запуск всех сайтов

1. У каждого нужного источника включите флаг `Использовать в общем запуске` и установите статус доступа `Публичный доступ`.
2. В workflow нажмите `Запустить`.
3. Выберите `Запустить все публичные источники`.

Сервис создаёт **отдельный run на каждый источник**. Ошибка одного сайта не отменяет остальные.

## 7. Как понять результат запуска

Откройте `Запуски` и нажмите на строку последнего run.

| Статус | Значение | Что делать |
| --- | --- | --- |
| `SUCCESS` | Workflow завершился. | Проверьте итог, artifacts и dataset. |
| `WAITING_FOR_REVIEW` | Данные собраны и ждут проверки. | Откройте `Проверка данных`. |
| `FAILED` | Один из узлов завершился ошибкой. | Откройте run и найдите узел со статусом ошибки. |
| `QUEUED` / `RUNNING` | Run ожидает/выполняется. | Обновите страницу через несколько секунд. |
| `CANCELLED` | Run отменён. | Запустите повторно при необходимости. |

### Что проверять в run

1. В разделе `Узлы` откройте каждый узел: вход и выход помогут понять, где исчезли данные.
2. В `Artifacts` скачайте raw-страницу/документ. Это первоисточник для проверки, а не итог модели.
3. В `Итог` проверьте количество records и сообщения о сохранении в dataset.

### Частые ошибки

| Сообщение или симптом | Причина | Исправление |
| --- | --- | --- |
| `HTTP Request: URL не задан` | Не выбран источник запуска. | Вверху workflow выберите источник. |
| `Dataset не найден` | Dataset удалён или workflow ссылается на старый dataset. | Выберите существующий dataset в настройках workflow и Output. |
| `Natural key обязателен` | Не задан ключ уникальности. | Заполните natural key в dataset или Output. |
| `Save Dataset требует явный Mapping business records` | Нет узла Mapping или он не подключён/не настроен. | Настройте Mapping и соединения графа. |
| Успешный run, но 0 строк | Селектор/JSONPath не нашёл записи либо на странице нет данных. | Посмотрите raw artifact и протестируйте узел извлечения. |
| Ошибка 403/страница входа/CAPTCHA | Источник требует доступ или запрещает автоматическое чтение. | Пометьте `Нужен доступ`; не обходите защиту без разрешённого доступа. |

## 8. Проверка качества данных

Откройте `Проверка данных`.

Для финансовых данных после каждого запуска необходимо:

1. Открыть 3–5 задач `Контрольная выборка` или новых записей.
2. Открыть `source_url` или raw artifact из run.
3. Сверить минимум наименование, ставку, валюту, срок и минимальную сумму.
4. Нажать `Сверено`, если данные совпадают.
5. При ошибке использовать `Исправить` либо `Не совпадает`.

`Не совпадает` фиксирует проблему проверки. Для изменения значения используйте `Исправить`: это создаёт новую версию записи и сохраняет историю.

## 9. Просмотр и управление данными

Откройте `Данные` и выберите нужный dataset.

- `Все собранные` показывает в том числе первично ожидающие записи.
- `Подтверждённые — экспорт` показывает только записи, доступные для Excel, CSV, JSON и API.
- Нажатие на запись открывает историю версий.
- `Настройки dataset` меняют имя, slug, schema, natural key и политику review.
- `Очистить записи` удаляет записи и задачи проверки, но сохраняет сам dataset.
- `Удалить dataset` удаляет и dataset, и принадлежащие ему записи. Это необратимое действие в рамках приложения.

### Первый базовый срез

Если показана кнопка `Принять базовый срез (N)`, значит N первичных записей видны, но ещё не доступны для выгрузки.

Нажимайте её только после выборочной проверки raw-страниц. Действие подтверждает первые версии записей; будущие изменения по-прежнему будут попадать в проверку согласно policy.

## 10. Выгрузка Excel, CSV и JSON

1. Откройте `Данные`.
2. Выберите dataset.
3. Убедитесь, что счётчик `Подтверждено и доступно для экспорта` больше нуля.
4. Нажмите нужную кнопку:
   - `XLSX` — Excel;
   - `CSV` — табличная выгрузка;
   - `JSON` — интеграции и программная обработка.

В выгрузку попадают только `APPROVED` записи. Если кнопки неактивны, проверьте `Проверка данных` или примите базовый срез после сверки.

## 11. Получение данных по API

API требует Bearer-токен пользователя. Интерактивная документация доступна по адресу `/api/docs` на вашем сервере.

### Вход

```http
POST /api/v1/auth/login
Content-Type: application/json

{
  "email": "your-user@example.com",
  "password": "your-password"
}
```

Из ответа возьмите `access_token` и передавайте его в заголовке:

```http
Authorization: Bearer <access_token>
```

### Найти datasets

```http
GET /api/v1/datasets
Authorization: Bearer <access_token>
```

Возвращает `id`, `name`, `slug`, `project_id`, natural key и политику проверки.

### Прочитать подтверждённые записи dataset

```http
GET /api/v1/datasets/<dataset_id>/records?limit=100&offset=0
Authorization: Bearer <access_token>
```

По умолчанию возвращаются только подтверждённые записи. Для диагностического просмотра первичных непроверенных данных добавьте `include_pending=true`; не публикуйте их без проверки.

### Скачать файл через API

```http
POST /api/v1/exports?dataset_id=<dataset_id>&format=xlsx
Authorization: Bearer <access_token>
```

Допустимые `format`: `xlsx`, `csv`, `json`.

## 12. Еженедельное расписание

Перед расписанием workflow должен быть опубликован, а все источники должны быть включены и иметь публичный доступ.

1. В настройках workflow включите `Расписание запускает все публичные источники проекта`.
2. Нажмите `Сохранить draft` → `Опубликовать`.
3. Откройте `Расписания` → `Создать расписание`.
4. Обязательные поля:

| Поле | Пример |
| --- | --- |
| `Workflow` | Опубликованный workflow. |
| `Название` | `Еженедельный мониторинг ставок`. |
| `Cron` | `0 8 * * 1` — каждый понедельник в 08:00. |
| `Часовой пояс` | `Europe/Minsk`. |

После автоматического запуска проверьте `Запуски`, затем `Проверка данных`, и только потом используйте Excel/API.

## Финальный чек-лист перед передачей результата

- [ ] Источник создан в нужном проекте, доступен и включён.
- [ ] Dataset создан в том же проекте.
- [ ] Natural key задан и соответствует полям Mapping.
- [ ] Workflow создан из шаблона, dataset выбран, Mapping настроен.
- [ ] Workflow сохранён, проверен и опубликован.
- [ ] В ручном запуске выбран конкретный источник.
- [ ] Последний run имеет `SUCCESS` или `WAITING_FOR_REVIEW`.
- [ ] Скачан raw artifact и выборочно сверены значения.
- [ ] Новые/изменённые записи подтверждены либо базовый срез принят после проверки.
- [ ] В `Данные` есть подтверждённые записи.
- [ ] XLSX/CSV/JSON успешно скачивается или API отдаёт записи.
