# Руководство пользователя Parser Studio

Parser Studio — self-hosted конструктор для сбора данных с веб-страниц, JSON/API и документов. Работа строится по цепочке: **проект → источник → workflow → запуск → проверка → dataset / экспорт**.

## 1. Первый запуск и вход

1. В корне проекта создайте локальный файл настроек: `cp .env.example .env`.
2. До публикации сервиса замените все значения секретов в `.env`, особенно пароль PostgreSQL, ключи шифрования, ключи S3/MinIO и пароль администратора.
3. Запустите стек: `docker compose up --build`.
4. Откройте `http://localhost:8080`.
5. Введите email администратора и пароль из локального `.env` (`DEFAULT_ADMIN_EMAIL` и `DEFAULT_ADMIN_PASSWORD`).

После первого старта доступен демонстрационный проект с примером парсинга банковских депозитов. Его удобно использовать для знакомства с интерфейсом без доступа к внешнему сайту.

## 2. Роли

- **Administrator** — пользователи, секреты, подключения, AI providers и все операции разработки.
- **Developer** — проекты, источники, workflow, схемы и промпты.
- **Operator** — запуск workflow, просмотр данных, ручная проверка и экспорт.
- **Viewer** — просмотр доступных результатов.

Если кнопка или раздел недоступны, обратитесь к администратору: это обычно означает недостаточную роль, а не ошибку браузера.

## 3. Быстрый сценарий: банковская страница

1. Откройте **Проекты** и создайте проект. Slug должен состоять из строчных латинских букв, цифр и дефисов.
2. Перейдите в **Источники → Добавить URL**.
3. Вставьте страницу с тарифами и нажмите **Запустить Source Profiler**.
4. Изучите рекомендацию:
   - `HTTP` — обычная статическая страница;
   - `Playwright` — контент появляется после JavaScript;
   - `JSON/XHR` — найдены API-запросы, обычно это наиболее надёжный путь;
   - `Document parser` — URL ведёт на PDF, XLSX, CSV или другой документ.
5. Выберите режим, проект и название, затем нажмите **Создать источник и workflow**.
6. В редакторе откройте узел `Repeating List`, задайте selector карточки и поля продукта.
7. Добавьте `Transform` с нормализацией `currency`, `term`, `rate`.
8. В правой панели workflow выберите Dataset, укажите natural key и review policy.
9. Нажмите **Проверить**, затем **Опубликовать** и **Запустить**.
10. Откройте **Проверка данных**, подтвердите или исправьте найденные записи.
11. Откройте **Данные**, выберите dataset и скачайте XLSX, CSV или JSON.

## 4. Источники и Source Profiler

В разделе **Источники** доступны два пути.

### URL-источник

Мастер выполняет HTTP-анализ, ищет таблицы, карточки, ссылки на документы, JSON-LD, формы, CAPTCHA и XHR/fetch. Когда нужен рендеринг JavaScript, он дополнительно пытается запустить Playwright.

Панель результата показывает рекомендованный режим, счётчики найденных таблиц, карточек, XHR/JSON endpoint и документов. Полная техническая диагностика остаётся доступна в раскрывающемся блоке.

### Документ как источник

Нажмите **Загрузить документ**. Поддерживаются PDF, DOCX, XLSX, CSV и JSON до 100 МБ.

1. Выберите проект и укажите понятное название источника.
2. Выберите файл. Сразу появится preview разбора.
3. Нажмите **Создать источник и workflow**.

Файл сохраняется как raw artifact, поэтому последующие запуски workflow используют именно загруженную версию документа. Созданный workflow содержит Download File → Parse Document → Save Dataset. Настройте Dataset и поля natural key перед публикацией.

## 5. Workflow Builder

Откройте workflow из списка или создайте новый. Центральная область — граф, слева — каталог узлов, справа — настройки выбранного узла либо настройки результата.

### Базовые действия

- Нажмите кнопку узла в каталоге, чтобы добавить его на canvas.
- Соедините порты узлов мышью. Для `Condition` есть отдельные ветки `true` и `false`.
- Нажмите узел на canvas, чтобы открыть его настройки справа.
- **Сохранить** — сохраняет реальное изменение графа.
- **Проверить** — валидирует DAG, неизвестные типы и циклы.
- **Опубликовать** — создаёт неизменяемую версию, которую используют запуски.
- **Запустить** — запускает текущий workflow синхронно и показывает итог в диалоге.
- **Тест узла** — выполняет только выбранный узел с текущими настройками.

Проверка или запуск неизменённого графа не создают новую версию workflow.

### Часто используемые узлы

- **HTTP Request** — HTTP/JSON/файл, headers, query parameters и JSON body.
- **Browser Open** — JavaScript-страница, browser actions, screenshot, rendered HTML и JSON/XHR capture.
- **Parse HTML / Parse Table / JSON Path** — детерминированный разбор HTML и JSON.
- **Repeating List** — карточки товара/тарифа и вложенные поля.
- **Parse Document** — PDF, DOCX, XLSX, CSV, JSON.
- **Transform / Formula** — очистка, regex, map, split/concat, число, валюта, срок и ставка.
- **LLM Extract / LLM Classify** — DeepSeek или другой OpenAI-compatible provider.
- **Validate** — required fields, диапазоны и JSON Schema.
- **Deduplicate / Condition** — обработка повторов и ветвления.
- **Save Dataset / Save External DB / Export File / Send Webhook** — публикация результата.

## 6. Визуальный selector picker

В настройках поля с кнопкой **Выбрать** нажмите её, укажите URL и выберите **Открыть**.

Если Playwright доступен, увидите screenshot страницы и интерактивные области поверх него. Наведите курсор на область либо элемент списка — соответствующий элемент подсветится. Нажмите его, чтобы записать предложенный CSS selector в поле. В списке показана оценка устойчивости selector:

- `HIGH` — ID, data-attribute или семантический атрибут;
- `MEDIUM` — стабильные классы;
- `LOW` — только имя тега.

Предпочитайте `HIGH` и `MEDIUM`. После выбора запустите **Тест узла** на реальном источнике. Если интерфейс сайта меняется, повторно выберите selector и сохраните новую версию workflow.

## 7. Схемы и качество данных

В **Схемы данных** создайте JSON Schema через конструктор полей. Задайте имя поля, тип (`string`, `number`, `integer`, `boolean`) и обязательность. Схема используется в узле `Validate`.

Рекомендуемая конфигурация для депозитов:

- `institution_name` — string, required;
- `product_name` — string, required;
- `currency` — string, required;
- `rate_value` — number;
- `term_min_days` и `term_max_days` — integer.

## 8. AI и DeepSeek

### Provider

Администратор открывает **Подключения → AI providers → Добавить**. Укажите имя, base URL, модель и ключ. Ключ шифруется на сервере и не возвращается через API.

Также основной DeepSeek provider можно настроить переменными `.env`: `DEEPSEEK_BASE_URL`, `DEEPSEEK_API_KEY`, `DEEPSEEK_DEFAULT_MODEL`.

### Prompt Manager

В **AI и промпты** создайте prompt: provider, модель, system prompt, user prompt и playground input. В prompt используйте `{{content}}` для подстановки переданного текста. Playground нужен для безопасной проверки результата до включения промпта в workflow.

Для предсказуемого результата задайте JSON Schema в узле `LLM Extract` и оставьте temperature близкой к нулю. LLM следует использовать как fallback для сложных случаев, а не вместо CSS, XPath или JSON API.

## 9. Запуски, raw artifacts и ошибки

В **Запуски** выберите строку запуска. В диалоге доступны:

- статус и ошибка workflow;
- вход и выход каждого узла, включая длительность;
- скачивание raw HTML, rendered HTML, screenshot, network capture и export artifact;
- **Повторить** — создаёт новый запуск с теми же входными данными;
- **Отменить** — помечает выполняющийся запуск как cancelled.

Отмена прекращает дальнейшую обработку в Parser Studio. Внешний браузерный или document-процесс может завершиться не мгновенно.

## 10. Review Queue и историзация

Если в настройках workflow включена проверка новых или изменённых значений, записи сначала появляются в **Проверка данных**.

- **Подтвердить** — публикует предложенное значение в dataset.
- **Исправить** — открывает JSON-редактор и сохраняет исправленную оператором версию.
- **Отклонить** — не публикует новую/изменённую запись.

Сравнение строится по natural key и хешу данных. Подтверждённые версии доступны в каталоге данных; ожидающие и отклонённые не попадают в пользовательский экспорт.

## 11. Data Explorer и экспорт

Откройте **Данные**, выберите dataset и используйте кнопки XLSX, CSV или JSON. Таблица показывает только активные подтверждённые записи. При больших наборах используйте кнопки **Назад** и **Вперёд**: интерфейс получает данные страницами по 100 строк.

В **Экспорт** приведена краткая справка. Экспорт также можно сделать отдельным узлом `Export File` прямо в workflow; тогда файл сохранится как artifact запуска.

## 12. Внешние базы и webhook

В **Подключения → Базы данных** администратор добавляет PostgreSQL, MySQL/MariaDB или SQLite. Пароль хранится в зашифрованном виде. В узле `Save External DB` задайте:

1. имя подключения;
2. разрешённую таблицу;
3. mapping полей;
4. режим insert или upsert;
5. conflict keys для upsert.

Не указывайте пользовательский SQL: узел строит операции через SQLAlchemy. Для отправки данных во внешнюю систему используйте `Send Webhook` с URL, headers и путём к payload.

## 13. Расписания

В **Расписания** создайте задание, выберите workflow, имя, пятичастное cron-выражение и часовой пояс. Пример еженедельного запуска в понедельник в 08:00: `0 8 * * 1`.

Перед созданием расписания опубликуйте workflow и обязательно выполните ручной тест. Celery Beat проверяет расписания раз в минуту.

## 14. Пользователи, секреты и audit log

- В **Пользователи** администратор создаёт учётные записи и назначает роли.
- В **Подключения → Секреты** хранятся значения, которые могут использоваться в workflow через `{{secret.ИМЯ}}`.
- В **Audit log** отображаются операции создания, изменения, публикации, review и настройки.

Не вводите секреты в URL, selector, prompt или JSON артефакта: эти значения могут попасть в историю запуска. Для токенов используйте раздел секретов.

## 15. Диагностика и обслуживание

Проверки сервиса:

```bash
curl http://localhost:8080/api/v1/health
curl http://localhost:8080/api/v1/ready
docker compose ps
docker compose logs -f api worker-general worker-browser worker-document worker-llm
```

Регулярно делайте backup PostgreSQL и MinIO. Команды приведены в `README.md`. После обновления кода выполняйте:

```bash
docker compose up -d --build
python3 -m pytest -q
python3 scripts/smoke_test.py
```

## 16. Новости БВФБ: полный исторический архив и обновления

Для этого сценария не требуется вручную строить цикл по ссылкам. В **Проекты → Создать проект** выберите шаблон **«Новости БВФБ — полный архив и обновления»**, задайте название, например `Новости БВФБ`, slug `bcse-news`, часовой пояс `Europe/Minsk` и русский язык.

Шаблон создаёт источник, схему `BCSE News`, dataset и два готовых workflow:

- **BCSE News — Historical Backfill** — архивная загрузка всего доступного календарного архива;
- **BCSE News — Incremental** — новые и недавно изменённые публикации за последние 45 дней.

Оба workflow используют узел **Crawl Links / Новости**. Это явный fan-out/fan-in узел, поэтому нет скрытой вложенной логики: он получает массив ссылок, запрашивает каждую страницу с заданными concurrency, retry, timeout и delay, после чего возвращает одну запись на статью. Ошибки отдельных страниц показываются в `errors` и не теряют результаты остальных.

### Как устроен готовый источник

Проверенная на 31.07.2026 конфигурация БВФБ:

| Настройка | Значение |
| --- | --- |
| Исторический API | `https://www.bcse.by/press_center/calendar` |
| Период backfill | `sFrom=01.01.2000`, `sTo=31.12.2035` |
| Массив записей | `tabs.0.contents` |
| Фильтр URL / ID | `/press-center/news/(n[^/?#]+)` |
| Заголовок | `#title` |
| Дата | `.dynamic-publicationdate` |
| Центральный текст | `#pc_body` |

Календарь возвращает в одном ответе все доступные материалы; узел отбирает только URL `/press-center/news/`, не смешивая новости с релизами. На дату проверки архив новостей начинался 04.02.2021. Если БВФБ расширит архив, повторный backfill автоматически обнаружит дополнительные ссылки.

`news_id` извлекается из URL (`n...`), query-параметры и `#fragment` удаляются из канонического URL. Страница даёт `title`, `published_at`, `body_text`, `body_html`, `tags`, `attachments_json`, `language=ru`, `source_name=БВФБ` и `observed_at`. Вложения внутри `#pc_body` собираются для PDF/DOC/DOCX/XLS/XLSX/ZIP. Raw JSON листинга и raw HTML каждой статьи сохраняются в artifacts запуска.

### Первый запуск

1. Откройте `BCSE News — Historical Backfill`.
2. Нажмите узел **Crawl Links / Новости** и сначала задайте `max_items = 3`.
3. Нажмите **Тест узла**. Проверьте: `count=3`, все `news_id` начинаются с `n`, а `body_text` не содержит footer и рыночные котировки.
4. Верните `max_items = 5000`, сохраните и нажмите **Проверить**.
5. В настройках workflow убедитесь, что Dataset — `BCSE News`, а natural key — `news_id`.
6. Опубликуйте workflow и выполните ручной запуск. Новые исторические записи создаются без Review Queue, а изменения направляются на проверку.

Не создавайте расписание до успешного теста ограниченной выборки. Для регулярной работы опубликуйте `BCSE News — Incremental` и создайте расписание `*/30 * * * *` с часовым поясом `Europe/Minsk`. Его окно 45 дней позволяет увидеть новые и недавние исправленные публикации. Чтобы контролировать изменения в более старых статьях, запускайте `Historical Backfill` вручную или отдельным еженедельным/ежемесячным расписанием: natural key и стабильный хеш не создадут дубликатов.

### Проверка качества и адаптация

После запуска откройте **Запуски** и проверьте результат узла: `discovered`, `count`, `errors`, `records`. Откройте несколько raw HTML разных лет. Валидная запись имеет непустые `news_id`, `title`, `published_at`, `url`, `body_text`; URL содержит `/press-center/news/`.

`observed_at`, технический HTTP status, evidence и ссылка на raw artifact не участвуют в сравнительном хеше. Поэтому повторная загрузка неизменной публикации не создаёт ложную новую версию; изменение заголовка, даты, текста, тегов или вложений создаёт версию и, по умолчанию, задачу проверки.

Если сайт поменяет разметку, не переписывайте workflow: откройте selector picker из полей `Selector заголовка`, `Selector даты` или `Selector текста статьи`, выберите элемент на screenshot и протестируйте ограниченную выборку. Если API календаря перестанет быть доступен, оставьте `listing_url` пустым, передайте HTML от `Browser Open`, выберите `Selector ссылок`, и тот же узел выполнит обход HTML-ссылок.

## 17. Границы текущего MVP

Это single-tenant система. Не входят в текущую реализацию: multi-tenant isolation, noVNC-интерфейс интерактивного логина к сайту, GraphQL-конструктор, email trigger/output, визуальные join/group/fuzzy/SCD2 операции и подтверждённая нагрузочная квалификация на миллионах записей.

Selector picker предоставляет screenshot с интерактивными областями и список кандидатов, но не заменяет ручную проверку selector на нескольких страницах. Для критичных финансовых данных оставляйте review policy включённой.
