# Аудит frontend — Parser Studio

Дата аудита: 12 августа 2026.  
Область: `apps/frontend`, production-конфигурация Nginx и клиентские зависимости.  
Изменения в исходный код frontend не вносились.

## Методика и ограничения

- Выполнен статический анализ TypeScript/React/CSS, клиентской авторизации, маршрутизации и production-сборки.
- Выполнены: `npm run lint`, `npm run test` (5 тестов), `npm run build`, `npm audit` и `npm audit --omit=dev`. Все команды завершились успешно; известных CVE в текущем дереве npm-зависимостей не найдено.
- Выполнена проверка адаптивной вёрстки по CSS-правилам и breakpoint’ам. Попытка войти в локальный UI для полной визуальной проверки остановилась на `HTTP 500` от `/api/v1/auth/login`: в среде аудита API не запущен/недоступен корректно. Поэтому замечания с пометкой **«визуальная вёрстка»** подтверждены правилами CSS и структурой DOM, но не скриншотами наполненных страниц.

## Что не найдено

- Статический поиск не выявил в frontend `dangerouslySetInnerHTML`, `innerHTML`, `eval` или `new Function`.
- Значения, выводимые через JSX, экранируются React по умолчанию; прямой DOM-XSS в текущем коде не обнаружен.
- `npm audit` не обнаружил известных уязвимостей ни для production-зависимостей, ни для полного dependency tree на дату аудита.

## Рекомендуемый порядок работ

1. FE-01, FE-02, FE-03: защита и корректное завершение сессии, восстановление мобильной навигации.
2. FE-07–FE-12: устойчивость ключевых операций и исправление workflow-редактора на tablet/mobile.
3. FE-04–FE-06, FE-13–FE-21: hardening, роли, доступность, адаптивные представления данных и контракты API.
4. FE-22–FE-25 и очистка лишних частей: качество, тестирование и поддерживаемость.
